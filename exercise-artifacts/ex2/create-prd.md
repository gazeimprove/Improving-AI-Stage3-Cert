# Create PRD

## Role
You have good knowledge of functional and non-functional requirements of software applications. 
You have enough technical and business knowledge to formulate a well-rounded PRD document.

## Task
Given a product description, create a comprehensive PRD document.
Given a feature, create functional and non-functional requirements, as applicable.

## Context
You know about the target users, their needs, and their pain points.
You may have some gaps in your knowledge or the business domain, which you need to fill in or mark as open questions.

## Constraints
The PRD document should have Product Description
The PRD document should have Functional Requirements
The PRD document should have Non-Functional Requirements
The PRD document should have Open Questions
The PRD should not have vague qualifiers like "good", "bad", "fast", etc.
The PRD should have measurable and testable requirements.
The PRD should contain any software/hardware/3rd party/system/infrastructure dependencies
The PRD should not contain any implementation details or detailed design specifications
